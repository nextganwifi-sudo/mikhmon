# সম্পূর্ণ সফটওয়্যার স্পিড ও রিলায়েবিলিটি অডিট এবং সিস্টেম শিডিউলার পারমিশন কন্ট্রোল প্ল্যান

এই প্ল্যানে পুরো **NextGan WiFi Solution** সফটওয়্যারের প্রতিটি অপশন ও মডিউলের গভীর অডিট রিপোর্ট, যেসব কারণে সফটওয়্যারটি রিয়েল রাউটারে ধীরগতির হতে পারে তার স্থায়ী সমাধান এবং পারমিশন গ্রুপের মধ্যে **System Scheduler** পারমিশন যুক্ত করে ডিফল্টভাবে রিসেলারদের জন্য বন্ধ রাখার সম্পূর্ণ পরিকল্পনা তুলে ধরা হয়েছে।

### User Review & Critical Decisions

> [!IMPORTANT]
> নিচের সিদ্ধান্তগুলো আপনার নির্দেশনা অনুযায়ী চূড়ান্ত করা হয়েছে। অনুমোদন (**Proceed**) দিলেই সাথে সাথে কোডে বাস্তবায়ন করা হবে।

- **সিস্টেম শিডিউলার (System Scheduler) পারমিশন নিয়ন্ত্রণ**: পারমিশন গ্রুপের (Permission Groups) তালিকায় **System Scheduler** (`View System Scheduler` এবং `Manage System Scheduler`) আলাদা ও স্পষ্ট ক্যাটাগরি হিসেবে যুক্ত করা হবে। ডিফল্টভাবে সব রিসেলার পারমিশন গ্রুপে (`Read`, `Write`, `Full`, `Reset Voucher`) এবং বর্তমান রিসেলারদের ক্ষেত্রে এটি **বন্ধ (`Unchecked / False`)** থাকবে, যাতে কোনো রিসেলার শিডিউল অপশন দেখতে বা ব্যবহার করতে না পারে। শুধুমাত্র অ্যাডমিন চাইলে নির্দিষ্ট কোনো গ্রুপে বা রিসেলারকে টিক দিয়ে পারমিশন দিতে পারবেন।
- **ভাউচার পেজের (Vouchers / User by Profile) মারাত্মক N+1 API স্লোনেস ফিক্স**: অডিটে দেখা গেছে, ভাউচার পেজে গেলে সফটওয়্যারটি প্রতিটি প্রোফাইলের জন্য আলাদা আলাদা করে রাউটারে নেটওয়ার্ক রিকোয়েস্ট পাঠায় (যেমন ১৫টি প্রোফাইল থাকলে ১৭ বার রাউটারে হিট করে)। এটি পরিবর্তন করে মাত্র ১ বার ইউজার লিস্ট এনে PHP মেমোরিতে `<1ms` সময়ে প্রোফাইল অনুযায়ী গণনা করা হবে—ফলে ভাউচার পেজ ৫ থেকে ১০ গুণ দ্রুত লোড হবে।
- **বাকি সব মডিউলের ডাবল রাউটার রিকোয়েস্ট (`count-only`) ও ডুপ্লিকেট কানেকশন অপসারণ**: Hotspot Active, Hosts, IP Binding, Cookies, DHCP Leases, System Scheduler এবং Selling Report পেজে রাউটারে যে অতিরিক্ত ডুপ্লিকেট রিকোয়েস্ট ও কানেকশন যাচ্ছিল, তা সম্পূর্ণ বন্ধ করে সিঙ্গেল-পাস প্রসেসিং করা হবে।

### ১. ওভারভিউ ও অডিট ফাইন্ডিংস (Full Software Audit Summary)

পুরো সফটওয়্যারের প্রতিটি মেনু এবং ব্যাকএন্ড অপশন অডিট করে নিচের সমস্যাগুলো চিহ্নিত করা হয়েছে:

1. **কেন রিসেলাররা এখনো System Scheduler দেখতে পাচ্ছিল?**
   - ডিফল্ট পারমিশন গ্রুপ ডেফিনিশনে (`Read`, `Write`, `Full`) আগে থেকেই `view_scheduler = true` দেওয়া ছিল এবং পারমিশন গ্রুপের UI-তে এটি `'Router Management'`-এর ভেতরে লুকানো ছিল।
   - এর ফলে যেকোনো রিসেলার লগইন করলেই বাম পাশের মেনুতে `System -> Scheduler` দেখতে পেত এবং শিডিউল পেজে ঢুকতে পারত।
2. **ভাউচার পেজে (Vouchers) লুপের ভেতরে রাউটার API কল (N+1 Query Bottleneck)**:
   - ভাউচার পেজে (`Hotspot -> Vouchers`) যতগুলো প্রোফাইল থাকে, লুপ ঘুরিয়ে ততবার রাউটারে `/ip/hotspot/user/print (count-only)` কমান্ড পাঠানো হচ্ছিল। বাংলাদেশ থেকে সৌদি আরব ভিপিএস এবং সেখান থেকে মাইক্রোটিক রাউটারের ল্যাটেন্সিতে ১৫–২০টি প্রোফাইল থাকলে পেজটি লোড হতে ৪–৮ সেকেন্ড আটকে থাকত।
3. **৬টি পেজে ডাবল API কল (`print` + `count-only`)**:
   - **Hotspot Active**, **Hosts**, **IP Bindings**, **Cookies**, **DHCP Leases**, এবং **System Scheduler**—এই ৬টি পেজে প্রথমে সব ডাটা (`print`) আনা হয় এবং ঠিক পরের লাইনেই আবার শুধুমাত্র সংখ্যা গোনার জন্য দ্বিতীয়বার রাউটারে (`count-only`) রিকোয়েস্ট পাঠানো হয়। অথচ প্রথমবার আনা ডাটার `count()` থেকেই মুহূর্তে সংখ্যা পাওয়া যায়।
4. **সেলিং রিপোর্টে (Selling Report) ডুপ্লিকেট রাউটার কানেকশন**:
   - মেইন রাউটার কানেকশন চালু থাকা সত্ত্বেও সেলিং রিপোর্ট পেজে গিয়ে নতুন করে আবার `$API->connect()` কল করা হচ্ছিল, যা অহেতুক দ্বিতীয়বার TCP হ্যান্ডশেক ও লগইন করায়।
5. **অস্তিত্বহীন ফাইল ইনক্লুড (`info.php`)**:
   - মেনু এবং অ্যাডমিন প্যানেলে প্রতিবার পেজ লোডের সময় এমন একটি `info.php` ফাইল খোঁজা হচ্ছিল যা ডিস্কে নেই।

### ২. ইউজার এক্সপেরিয়েন্স ও ভিজ্যুয়াল ডিজাইন (UX & Permission Group Flow)

- **পারমিশন গ্রুপে স্পষ্ট "System Scheduler" সেকশন**:
  - `Admin Panel -> Permission Groups` এবং রিসেলারের `Custom Permissions` মডালে **System Scheduler** নামে একটি নিবেদিত ও স্পষ্ট ক্যাটাগরি থাকবে:
    - `View System Scheduler (Menu & List)` — শিডিউল মেনু ও তালিকা দেখা (ডিফল্ট: **বন্ধ / অফ**)
    - `Manage System Scheduler (Enable / Disable / Remove)` — শিডিউল পরিবর্তন বা ডিলিট করা (ডিফল্ট: **বন্ধ / অফ**)
- **মেনু ও রাউট সুরক্ষা (Zero-Leakage Enforcement)**:
  - কোনো রিসেলারের `view_scheduler` পারমিশন না থাকলে বাম পাশের সাইডবারে **System** মেনু এবং **Scheduler** সাব-মেনু সম্পূর্ণ অদৃশ্য থাকবে।
  - কেউ সরাসরি URL লিখে (`?system=scheduler` বা শিডিউল অ্যাকশন) ঢোকার চেষ্টা করলেও সাথে সাথে তাকে অনুমোদিত পেজে রিডাইরেক্ট করে দেওয়া হবে।
- **তাৎক্ষণিক পেজ নেভিগেশন (Ultra-Fast Module Switching)**:
  - ইউজার লিস্ট, প্রোফাইল লিস্ট, ভাউচার, অ্যাক্টিভ ইউজার, হোস্ট, আইপি বাইন্ডিং, ডিএইচসিপি লিজ এবং সেলিং রিপোর্টে এক পেজ থেকে আরেক পেজে দ্রুত ক্লিক করলে কোনো ল্যাগ বা হ্যাং ছাড়াই পেজ ওপেন হবে।

### ৩. মূল কারিগরি সিদ্ধান্ত ও যৌক্তিকতা (Key Product Decisions & Trade-Offs)

- **সিদ্ধান্ত ১: ডিফল্টভাবে সব রিসেলার গ্রুপে শিডিউল পারমিশন `false` করা**
  - *পদ্ধতি*: `Read`, `Write`, `Full`, এবং `Reset Voucher`—এই ৪টি বিল্ট-ইন গ্রুপ ও বিদ্যমান রিসেলার প্রোফাইলগুলোতে `view_scheduler` ও `manage_scheduler` ডিফল্টভাবে `false` করে দেওয়া হবে।
  - *কেন*: মাইক্রোটিক রাউটারের সিস্টেম শিডিউলারে মেয়াদ শেষ হওয়া ইউজার ডিলিট বা রাউটার রিবুটের মতো সংবেদনশীল স্ক্রিপ্ট থাকে। রিসেলারদের এটি দেখার বা পরিবর্তনের প্রয়োজন নেই এবং এটি গোপন রাখা নিরাপত্তার জন্য অপরিহার্য।
- **সিদ্ধান্ত ২: রাউটার API কল ন্যূনতম করা (In-Memory Aggregation over Network Round-Trips)**
  - *পদ্ধতি*: ভাউচার পেজে প্রোফাইলভিত্তিক ইউজার গোনার জন্য লুপের ভেতরে রাউটারে বারবার রিকোয়েস্ট না পাঠিয়ে একবার ইউজার লিস্ট এনে PHP মেমোরিতে হ্যাশ-ম্যাপ (`O(N)`) দিয়ে গণনা করা হবে।
  - *কেন*: ১ কোর সিপিইউ ও দূরবর্তী ভিপিএস নেটওয়ার্কে সবচেয়ে বড় বটলনেক হলো রাউটারের সাথে বারবার নেটওয়ার্ক রাউন্ড-ট্রিপ (RTT)। নেটওয়ার্ক কল ১৭টি থেকে কমিয়ে ২টিতে নামিয়ে আনলে পেজ লোডিং টাইম ৮৫% পর্যন্ত কমে যাবে।

#### ইন্টারঅ্যাক্টিভ কম্পোনেন্ট ও স্টেট ম্যাপিং
- **পারমিশন গ্রুপ ম্যানেজমেন্ট**: অ্যাডমিন যখন `Settings -> Permission Groups`-এ যাবেন, তখন **System Scheduler** ক্যাটাগরির অধীনে স্পষ্টভাবে শিডিউলের পারমিশন দেখতে পাবেন এবং যেকোনো গ্রুপের জন্য চেক/আনচেক করে সেভ করতে পারবেন।
- **ভাউচার ও হটস্পট মডিউল**: ইউজার যখন ভাউচার বা হটস্পটের যেকোনো সাব-মেনুতে ক্লিক করবেন, তখন রাউটার থেকে একবারেই প্রয়োজনীয় ডাটা নিয়ে সাথে সাথে কার্ড ও টেবিল রেন্ডার হবে।
